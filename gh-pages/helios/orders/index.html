How the algorithm works
01 / INPUT
Use only known closes
Pull roughly 150 calendar days of NVDA daily TRDPRC_1 from LSEG. Require 50 valid closes and require the newest close to match the last completed NASDAQ session.
02 / SIGNAL
Compare moving averages
If the mean of the last 20 closes exceeds the mean of the last 50 closes, target 1 share. Otherwise, target 0. The strict comparison puts ties in cash.
03 / ORDERS
Trade the difference
Read mkt/positions.json when present. Buy the shares needed to reach 1 or sell shares needed to reach 0. If already at target, write [].

The same rule, run over LSEG daily bars since late 2020. The backtest calls the exact function the nightly job uses (signal_from_closes), decides at each close, and fills at the next day's open, the way a Sanji market order would. Returns are split at the open, so the overnight gap belongs to the old position and the day's move to the new one. No commissions or slippage. Prices are split-adjusted. What it shows

      
As of the 2026-11-19 run, the rule turned $1 into about $3.89; holding NVDA turned it into about $10.75. The rule was in the market 64% of days and ran at lower volatility (38% vs 51%), but its Sharpe ratio was lower (0.80 vs 1.06). On a stock that rose tenfold, being out a third of the time is expensive: in 2023 the rule made +150% while holding made +246%.

      
It also did not deliver the protection a trend filter promises. It exited in January 2022, about 17% below the November 2021 peak, but then bought two bear-market rallies, in March and August 2022, and sold each about 30% lower. It lost 59% in 2022 against 51% for holding, and its worst drawdown (−65%) was almost the same as holding's (−66%). Where it helped is the recent decline: down 8% in 2026 against 23% for holding, and flat since the exit on 2026-11-02, which is why tonight's order file is empty.

      
Limits: one stock, one path, and NVDA was picked after it had already risen, which flatters any long rule. Seventeen round trips over six years make costs negligible, so they are left out. The live strategy trades one share, so the dollar results are small; the percentages are what matter.

When it runs
The workflow is scheduled for 03:00 UTC, which is 10 p.m. New York in winter and 11 p.m. in summer, following the course's nightly refresh. GitHub starts scheduled jobs late when its runners are busy. On this repo the scheduled run has actually started around 11:00 UTC, about 6 a.m. New York, which is still before the 9:30 open.
The script therefore does not trust the calendar date. It asks the NASDAQ calendar for two sessions measured against the current time: the last session that has already closed, whose close must be the newest LSEG bar, and the first session that has not yet opened, which becomes the order's for date. An on-time run at 10 p.m. Monday and a late run at 6 a.m. Tuesday both plan Tuesday from Monday's close. A manual run during market hours ignores the partial bar and plans the following session. If the newest close is missing, the job fails instead of writing orders from stale data.
After the script writes the files, the workflow commits them and starts the Pages deployment, so this page shows the same orders as the repo.

    
Why this design
A moving average rule is transparent and needs only daily stock prices. Holding at most one share keeps the assignment's order mechanics visible without options chain assumptions. The strategy reacts slowly to trend changes, may whipsaw in sideways markets, and uses the next session's market open, which can differ materially from the prior close.
The order id contains the session date and side, so a repeated nightly run for the same session produces the same identifier. Orders use NVDA's IB conid 4815747, the underlying contract, and only fields from the Sanji specification. A data fetch or calendar validation failure stops the job before either order file is overwritten.
The root open_orders.json satisfies the assignment's requested location. An identical mkt/open_orders.json supports the path in Sanji's published schema. The workflow commits both files and this page's signal data, then triggers Pages deployment.
Sanji fills orders from the prices the course machine stores, and it stores only the stocks listed in the repo's price_history.json. NVDA (conid 4815747) is listed there with "tracked": true, so the nightly price job collects its bars alongside the strategy's own LSEG pull.
